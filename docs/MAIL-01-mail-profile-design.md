# MAIL-01 — standalone mail profile handoff

Design version 1.0.0, 2026-11-12. **MAIL-01_READY_FOR_MAIL-02**.
This document specifies distribution integration; it implements no CLI/profile,
changes no package/version pins and triggers no production action.

The complete normative design is in the companion
[Infra Layer MAIL-01 dossier](https://github.com/drumee/infra-layer/tree/3244340/docs/mail-01).
It contains the versioned JSON Schema/examples, architecture, state model,
CLI specification, migration/rollback, read-only deployment audit and acceptance
matrix. Freeze the exact companion commit in MAIL-02's implementation baseline;
do not treat a mutable PR branch as a release acquisition reference.

| Debian / MAIL02 | Add `profiles/mail/{operator.js,lib/config.js,lib/distribution.js}` and exact source lock/build artifacts. New profile owns Postfix/OpenDKIM/Dovecot + auxiliary originating policy, resources, certificates and networks independently of Oxy/Ghost. |

| Debian / MAIL03 | Implement the specified `mail mailbox`, `mail alias`, `mail account` namespace in this operator, including revision/idempotency guards, generation barrier and protected FD/TTY password entry. MAIL01 is specification only. |
| Debian + Oxy / MAIL04 | Introduce optional versioned external mail-client dependency, endpoint/SAN/auth health probe and per-client secret projection. Do not express an absent owned `mail` service through `requires:[mail]`, add foreign networks, or bypass exact identity checks. |
| Debian / MAIL05 | Qualify standalone queue-specific recovery and storage boot guards. Retain existing `SMTP_RECOVERY_UNQUALIFIED` application guard; no generic spool-copy fallback. |
| Operator / MAIL06 | Authorized network/DNS/PTR/certificate installation and controlled migration; owner performs DNS/reverse updates. No such action is part of these design PRs. |

Proposed future invocation (not executable yet):

```text
drumee-ctl --profile mail validate --config /etc/drumee/mail.json
drumee-ctl --profile mail mail mailbox create contact@oxymot.fr ...
drumee-ctl --profile mail mail alias create hello@oxymot.fr --mailbox contact@oxymot.fr ...
drumee-ctl --profile mail mail account create oxyform ...
```

The normative operation grammar, flags, JSON envelopes/error exits, password input,
quota/rename/deletion/session semantics and transaction recovery are in
[operations.md](https://github.com/drumee/infra-layer/blob/3244340/docs/mail-01/operations.md).
In particular deletion retains Maildir by default; purge is separate. Rename keeps
UUID/Maildir/IMAP metadata; receiving, IMAP and submission flags are independent.
Oxy and Ghost accounts are SMTP-only, distinct and limited to approved senders.

## Qualification and release discipline

MAIL02 tests are isolated with synthetic data, no public bindings/real SMTP
egress. Native configuration must target qualified Dovecot 2.4 syntax and explicit
zero quota grace. The MAIL01 lab demonstrates LMTP/Maildir/IMAPS, service-specific
auth, quota tempfail and returned SASL generation after explicit config reload;
it does not qualify full transport or recovery. The companion matrix defines
MAIL02–06 gates, including a real isolated reboot and isolated restoration.

After implementation, acquire a newly published immutable producer only under
separate publication authorization. Update package/lock/member receipts together,
then qualify the installed consumer and distribution images. Run narrow profile/
schema/CLI tests and applicable shared `tests/run-all.sh`; inspect skips and retain
existing CI debt rather than weaken checks. No pin changes, release artifacts,
tag, merge or production operation are authorized by the design alone.

MAIL02 can start without knowing final DNS/UID/private-subnet allocations; use
isolated fixtures. Actual port25 permission, AAAA removal/qualification, PTR,
provider fallback, backup destination/RPO/RTO, mailbox inventory and sender grants
are explicit integration/activation gates in the companion dossier.
